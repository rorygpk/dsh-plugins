dsh-terminal-mode

A skin for the Harness Web GUI. It changes appearance and nothing else: colour, type, spacing, effects. Every control can be undone, and *Restore default skin* returns the interface to its original state.

  • Eight palettes: Default, Codex Terminal, Phosphor Green, Amber CRT, Tokyo Night, Nord, Solarized Light, Paper.
  • Adjustable brightness, background temperature, accent colour, corner radius, scanline intensity, text glow, and a monospace toggle.
  • A command palette (Ctrl/Cmd+Alt+K), shortcuts for switching and restoring, a statusline under the composer, and a >_ mark for empty sessions.
  • Appearance is stored in the browser's localStorage. The Harness profile is left untouched.

The implementation maps CSS custom properties on <html data-dsk> onto the application's --dsw-alias-* design tokens. New interface elements are rendered through published slots, so no component is replaced.

plugin_manager install_bundle({ target: "<repo>/plugins/dsh-terminal-mode" })

dsh-quick-provider

Adds an OpenAI-compatible provider with four fields: provider id, display name, base URL and API key.

  • Queries GET /models and registers every model the endpoint advertises.
  • Stores the key through the credential seam. The provider configuration holds only an environment-variable reference.
  • Available as a form under Settings > Models and as the add_llm_provider tool for sessions.

index.js performs discovery, stores the credential and writes the provider into the llm-pi-ai settings namespace, leaving streaming, retries and catalog resolution to the existing adapter. client.js renders the form.

plugin_manager install_bundle({ target: "<repo>/plugins/dsh-quick-provider" })

Install in your DSH

DeepSeek Harness is the agent runtime these plugins extend. If it is not installed yet, install it first. Then:

  1. Clone the repository.
    git clone https://github.com/rorygpk/dsh-plugins
  2. In a DSH session, install the plugin directory.
    plugin_manager install_bundle({ target: "<repo>/plugins/dsh-terminal-mode" })
plugin_manager install_bundle({ target: "<repo>/plugins/dsh-quick-provider" })
  3. Refresh the Harness window once so the client bundle loads.
LocationWhat appears
Settings > Terminal modeSkin cards, brightness, scanlines, palette shortcut
Settings > Models (lower section)Quick provider form
Sidebar >_ button, or Mod+Alt+KCommand palette

To uninstall, remove the bundle in the plugin manager, refresh the page and delete the directory. Terminal-mode preferences stay in the browser; provider entries stay in the profile until removed there.

Release archives are attached to each release as well. Extract one to a permanent location and point install_bundle at the extracted folder.

Compatibility

Built and tested against DeepSeek Harness 0.2.2-rc.1 (Web profile). A plugin is a directory whose package.json declares:

  • dsh.bundle.patch, the Cordis patch that inserts the plugin row;
  • dsh.client, the optional browser half loaded by the Web module loader;
  • locale/<lang>.json, the title and description shown by the plugin manager;
  • icon.svg, the artwork shown in the app.

Adding a plugin

Each plugin directory is self-contained, and CI and the release workflow discover it automatically:

  1. Create plugins/<name>/ with package.json, cordis.patch.yml, index.js (an inert apply() is enough), an optional client.js, locale/en.json, locale/zh.json and an icon.svg.
  2. Add a scripts/pack.ps1, copied from dsh-terminal-mode.
  3. Add README.md, README.zh.md, and a row to the table above.
  4. Run powershell -ExecutionPolicy Bypass -File scripts\pack-all.ps1 before tagging.

Direction

Two plugins exist today. What comes next will be decided the same way: by what is missing in daily use.

  • Further plugins under consideration: session export, workspace diff review, a prompt library, per-session model presets.
  • A plugin index listing compatible builds for each DSH release.
  • A starter template, so a new plugin begins from a working bundle.
  • Additional interface languages.
  • CI coverage against the DSH release line each plugin declares.

Issues and pull requests are welcome. The standard is modest and stays fixed: a plugin should be worth installing.

Releases

Pushing a v* tag builds every plugin archive on GitHub Actions and attaches each zip to that tag's release. Local builds are reproducible with scripts/pack-all.ps1.

dsh-terminal-mode

Harness 网页界面的皮肤。它只改变外观：配色、字体、间距与特效。所有设置都可以撤销， “还原默认皮肤”会把界面恢复到初始状态。

  • 八套配色：默认、Codex 终端、磷光绿、琥珀 CRT、东京夜色、北境、Solarized 浅色、纸白。
  • 可调亮度、背景色温、强调色、圆角、扫描线强度、文字辉光，以及等宽字体开关。
  • 命令面板（Ctrl/Cmd+Alt+K）、切换与还原快捷键、输入框下方状态栏，以及空会话的 >_ 标记。
  • 外观保存在浏览器的 localStorage 中，不写入 Harness profile。

实现方式是把 <html data-dsk> 上的 CSS 自定义属性映射到应用的 --dsw-alias-* 设计令牌； 新增界面全部通过公开插槽渲染，不替换任何组件。

plugin_manager install_bundle({ target: "<仓库路径>/plugins/dsh-terminal-mode" })

dsh-quick-provider

用四项输入添加一个 OpenAI 兼容提供商：提供商 ID、显示名称、API 地址、API Key。

  • 请求 GET /models，注册该端点声明的每个模型。
  • 通过凭据通道保存密钥；提供商配置里只保留环境变量引用。
  • 既可以在 设置 > 模型 的表单中操作，也可以由会话调用 add_llm_provider 工具完成。

index.js 负责模型发现、保存凭据，并把提供商写入 llm-pi-ai 设置命名空间，流式、重试与 目录解析仍由既有适配器承担；client.js 只渲染表单。

plugin_manager install_bundle({ target: "<仓库路径>/plugins/dsh-quick-provider" })

安装到你的 DSH

DeepSeek Harness 是这些插件所扩展的 Agent 运行时。如果尚未安装，请先安装，然后：

  1. 克隆仓库。
    git clone https://github.com/rorygpk/dsh-plugins
  2. 在 DSH 会话中安装插件目录。
    plugin_manager install_bundle({ target: "<仓库路径>/plugins/dsh-terminal-mode" })
plugin_manager install_bundle({ target: "<仓库路径>/plugins/dsh-quick-provider" })
  3. 刷新一次 Harness 窗口，让客户端 bundle 生效。
位置内容
设置 > 终端模式皮肤卡片、亮度、扫描线、命令面板快捷键
设置 > 模型（页面上部下方）快速添加提供商表单
侧边栏 >_ 按钮，或 Mod+Alt+K命令面板

卸载时，在插件管理器中移除 bundle，刷新页面并删除目录。终端模式的外观偏好仍留在浏览器中； 提供商条目会保留在 profile 里，直到手动移除。

每个插件也会以独立 zip 附在对应的 Release 上。解压到固定位置后，把 install_bundle 指向解压目录即可。

兼容性

基于 DeepSeek Harness 0.2.2-rc.1（Web profile）构建并测试。插件是一个目录，其 package.json 声明：

  • dsh.bundle.patch：插入插件行的 Cordis 补丁；
  • dsh.client：可选的浏览器半部，由 Web 模块加载器加载；
  • locale/<lang>.json：插件管理器中显示的标题与描述；
  • icon.svg：应用内展示的图标。

新增插件

每个插件目录自成一体，CI 与发布工作流会自动发现：

  1. 新建 plugins/<name>/，放入 package.json、cordis.patch.yml、index.js （空的 apply() 即可）、可选的 client.js、locale/en.json、locale/zh.json 与 icon.svg。
  2. 添加 scripts/pack.ps1，可从 dsh-terminal-mode 复制。
  3. 补上 README.md、README.zh.md，并在上表增加一行。
  4. 打标签前运行 powershell -ExecutionPolicy Bypass -File scripts\pack-all.ps1。

方向

目前有两个插件。下一步做什么，同样由日常使用中缺少什么来决定。

  • 正在考虑的插件：会话导出、工作区 diff 审阅、提示词库、按会话的模型预设。
  • 一个按 DSH 版本列出兼容构建的插件索引。
  • 一套起始模板，让新插件从一个可用的 bundle 开始。
  • 更多界面语言。
  • 针对各插件所声明 DSH 版本线的 CI 覆盖。

欢迎 issue 与 pull request。标准不高，但不会改变：插件应当值得安装。

发布

推送 v* 标签后，GitHub Actions 会构建每个插件的压缩包，并把 zip 附加到该标签的 Release。 本地可用 scripts/pack-all.ps1 复现构建。
